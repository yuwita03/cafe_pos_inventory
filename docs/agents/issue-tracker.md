# Issue tracker: GitHub

Repository: yuwita03/cafe_pos_inventory.

Specs and implementation tickets published by engineering skills live
in GitHub Issues. Use the GitHub CLI with an explicit repository target.

Read the issue body, labels, and comments before working on an issue.
Use body files for multiline issue descriptions and comments.

Publish one issue per approved ticket. Use native blocking relationships
where available; otherwise record linked blockers in the issue body.
An implementation ticket is actionable only when its blockers are complete.

Publishing tickets does not authorize implementation or closing issues.
Follow repository approval and completion rules.

PRs as a request surface: no.

GitHub Issues track individual tickets. documents/TASKS.md remains the
project milestone and progress tracker; update only the assigned task's
permitted status, checklist, evidence, and blockers.
